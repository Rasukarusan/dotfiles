指定された変更が、なぜ必要だったのかを説明する。

## 対象

- 引数にファイル・行・コミット・PR 番号があれば、それを対象にする。
- 引数がなければ、この会話で直前に話題にした変更を対象にする。それもなければ、現在のブランチの `master` (または `main`) からの差分を対象にする。

## 調べるもの

上から順に、理由が分かった時点で止める。

1. この会話のやり取り
2. 該当行の `git log -L` / `git blame` で見つけたコミットのメッセージ
3. そのコミットを含む PR の説明とコメント (`gh pr list --search <sha> --state all` で探し、`gh pr view` で読む)
4. 変更前後のコードを比べ、変更がないと何が起きるか

## 出力

- 1 行目に結論 (何の問題を解決するための変更か) を書く。
- 続けて、変更がないと何が起きるかと、根拠 (コミット・PR 番号・会話のどこか) を 2〜4 行で書く。
- 根拠が見つからず推測で書く部分は「推測」と明記する。理由を作り上げない。
